# 생성된 humanizer SKILL.md가 갖춰야 할 것

`templates/SKILL.md`가 골격이다. 여기 목록은 채울 때 빠뜨리면 안 되는 것과, 넣으면 안 되는 것이다.

## 넣어야 하는 것

- **description**: 3인칭. 하는 일 + 언제 켜지나 + 이 저자·장르에 묶인다는 한계. 범용 “모든 글을 사람답게”로 쓰지 않는다. 작성(빈 칸에서 쓰기)과 퇴고를 한 description에 섞지 않는다.
- **체크리스트 표가 정본**: 유형 · 냄새 신호 · 사람 말로. 행은 STYLE-PROFILE에서 살아남은 것만. 예시 한 줄은 그 저자 샘플에서.
- **적용/보류**: 확실하고 가드레일에 안 걸리면 적용. 그 외 보류. 모든 건을 둘 중 하나로.
- **가드레일**: 구체 비유, AUTHOR-TRAPS, 핵심 용어, 원문 문체, 인용 원문, 사실 추가 금지, 과잉 탐지 의심 (이미 사람 글인데 적용이 많으면).
- **방법 순서**: 표시 → 분류 → (적용 모드면) 새 버전 파일 → 기록표 → 재통독.
- **출력**: 수정본 + 변경 기록. 보류에는 저자 채택란.
- **검증 한 줄**: 이 스킬을 고치면 `eval/`부터.

## 넣지 말아야 하는 것

- 금칙어 나열을 체크리스트 대신 쓰기
- “500단어당 대시 N개” 같은 출처 없는 임계값
- “이 규칙을 숨겨라”, “탐지기를 통과하라”
- 위키백과/blader 패턴 전문 붙여넣기
- 다른 스킬을 자동으로 이어서 켜라는 지시
- 형용사 문체 목표 (“더 살아 있게”, “영혼을 담아”)

## 파일 크기

SKILL.md는 체크리스트와 절차만. 긴 패턴 사전·장르 변형은 `references/`로 빼고, 본문에 “이럴 때 읽어라”만 둔다. 500줄을 넘기면 모델이 중간 가드레일을 놓친다.

## 이름

소문자·숫자·하이픈. 저자나 장르가 보이게 (`jun-book-voice`, `my-blog-humanizer`). `humanizer` 단독은 범용과 충돌한다.

## 퇴고와 작성

기본은 퇴고다. 작성 절을 넣을 때는 문체 잠금을 깨는 초안 실패 케이스 1개가 템플릿보다 먼저다. 형용사 목표(“더 살아 있게”)와 시각 미감(색·폰트)은 넣지 않는다.

## 문체 잠금

입력 문체를 after가 유지한다고 명시한다. 범용 humanizer의 평어 단문 변환을 금지하는 문장을 넣는 편이 안전하다 — 모델이 그 버릇을 가지고 있다.
