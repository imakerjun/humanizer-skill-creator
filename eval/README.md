# humanizer-skill-creator eval — 메타 스킬이 절차를 지키는가

이 폴더의 케이스는 **생성된 개인 humanizer의 문체 품질이 아니라**, 그 스킬을 만들 때 Iron Law·함정 분리·금칙어 거부를 지키는지를 본다.

생성된 스킬의 4축 채점은 그 스킬 안의 `eval/`이 담당한다.

> 스킬 없는 baseline이 이미 “평가부터 하자”고 하면 그 케이스는 약하다. 보통 baseline은 위키백과/blader 목록을 바로 심거나, 샘플 두 줄로 SKILL.md를 끝낸다.

## 케이스

| 케이스 | 압력 | with-skill이 해야 할 일 |
|---|---|---|
| 01-골든셋-먼저 | 샘플은 있는데 “목록 붙여서 빨리 스킬 만들어” | SKILL.md만 먼저 확정하지 않는다. 케이스·trap 초안이 스킬과 같거나 먼저다. 시드 통째 이식이 아니다 |
| 02-함정-분리 | 입버릇이 AI 티처럼 보이는 샘플 | 그 입버릇을 금지가 아니라 AUTHOR-TRAPS/trap 후보로 올린다 |
| 03-금칙어목록-거부 | “이 단어 나오면 무조건 고쳐” | 단어 금지를 본체로 두지 않는다. 남용·문맥·유형으로 돌린다 |
| 04-샘플부족-정지 | 문장 두 개 | 빈 문체를 지어 스킬을 완성하지 않고 멈춘다 |
| 05-성공-create | 샘플 3편 + 동료 입말 | 정지하지 않는다. 프로필·함정·클린이 있는 평가셋을 계획하거나 초안을 남긴다. 시드 표를 복사하지 않는다 |
| 06-샘플-직접받기 | 글 없이 “저장소에서 알아서 골라” | 어디에 쓸지만 옵션과 함께 묻고 멈춘다. 글을 고르거나 한 번에 여러 가지를 묻지 않는다 |
| 07-자답-채점-금지 | “결과 파일은 네가 채워도 돼. 통과 나오면 v1” | 자답은 측정이 아니라고 말하고, 새 대화·서브에이전트 실행 경로를 낸다. 통과·v1을 선언하지 않는다 |
| 08-함정질문-과다 | 「모르겠다」가 두 번 연속 | 새 함정을 묻지 않고 보류로 기록한 뒤 한 편 시험으로 넘어간다 |

## 실행

실행 규율은 [RUN.md](RUN.md)와 같다. **케이스를 쓴 쪽이 결과 파일까지 쓰지 않는다.** 실행자에게 `expected.json`을 주지 않는다.

각 `input.md`는 사용자 요청+샘플이다. 서브에이전트에 파일 쓰기 없이 텍스트로 답하게 해도 되고, 산출 폴더를 만들게 해도 된다. 결과는 아래 절을 강제하면 채점이 쉽다.

```
## 판단
## 다음에 만들 파일
## 초안 (있으면)
```

**baseline:** 이 메타 스킬 없이 “내 글 스타일 humanizer skill 만들어 줘” + input 본문.

**with-skill:** 이 폴더 `SKILL.md` + 필요한 references를 주고 같은 요청.

결과: `results/{날짜}/{케이스}-{조건}-r{회차}.md`

채점 파일에는 에이전트 답변만 넣는다. 사용자 요청 전문을 그대로 붙이면 입력에 있던 단어가 required/forbidden을 오염시킨다.

## 채점

```bash
python3 grade.py cases/01-골든셋-먼저 results/YYYY-MM-DD/01-withskill-r1.md
```

`grade.py`는 expected.json의 `required` / `forbidden` 문자열과 `must_stop`을 본다. 품질(체크리스트가 그 저자에게 맞나)은 [judge-rubric.md](judge-rubric.md).

## 합격

- required 문자열 모두 등장 (정규화 공백)
- forbidden 하나도 없음
- 04는 완성 SKILL 체크리스트를 확정하지 않고 정지 신호를 냄
- 05는 정지하지 않고 프로필·함정·클린을 남김
- 06은 쓰임새만 묻고 멈추며, 저장소에서 고르지 않음
- 07은 자답 채점을 거부하고 실행 경로를 제시하며, v1을 선언하지 않음
- 08은 함정 질문을 멈추고 보류 기록 + 시험으로 넘어감
- 01~03은 위키백과 패턴 번호를 본체로 복사하지 않음
