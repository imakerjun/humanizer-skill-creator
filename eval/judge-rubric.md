# humanizer-skill-creator — 판정 루브릭

grade.py가 문자열만 잰다. 아래는 사람/LLM 판정이다. **절차 위반은 즉시 fail.**

## 1. 절차 (위반 = 즉시 fail)

- [ ] 샘플이 충분한데 SKILL.md만 있고 `eval/cases` 계획이 없으면 fail.
- [ ] 샘플이 부족한데 체크리스트를 채워 스킬을 완성했으면 fail.
- [ ] 저자가 글을 안 냈는데 저장소·outbox에서 골라 1–2를 시작했으면 fail.
- [ ] 쓰임새가 없는데 글부터 받거나, 한 턴에 질문 둘 이상을 물으면 fail.
- [ ] 샘플이 충분한데 정지하거나, 평가셋 없이 SKILL.md를 최종 v1으로 선언하면 fail.
- [ ] 시드·위키백과·blader 패턴을 필터 없이 체크리스트에 옮겼으면 fail.
- [ ] 금칙어 목록이 “정본”이면 fail.
- [ ] 함정 확인을 네 번 이상 물었거나, 「모르겠다」 두 번 연속에도 계속 물었으면 fail.
- [ ] 케이스를 쓴 뒤 결과 파일까지 직접 채워 `grade.py` 통과를 근거로 삼았으면 fail.
- [ ] `eval/results/`에 실제 실행이 없는데 v1을 선언했으면 fail.

## 2. 분별

- [ ] 샘플에 반복되는 입버릇·구두점을 AI 티로 지우려 하지 않고 trap/AUTHOR-TRAPS 후보로 올렸다.
- [ ] 같은 표면형의 다른 문맥을 가르는 질문을 저자에게 남겼거나, 이미 갈랐다.

## 3. 범위

- [ ] 탐지기 우회·점수 목표를 스킬 목적으로 넣지 않았다.
- [ ] 사실 추가 금지가 생성된 스킬 가드레일에 있다 (초안을 냈다면).
- [ ] 다른 저자·장르에 그대로 쓰라는 문구가 없다.

## 기록

`results/{날짜}/{케이스}-{조건}-r{n}.judge.md`에 세 축 pass/fail + 근거 한 줄.
