# {{SKILL_NAME}} eval — 판정 루브릭 (사람 또는 LLM 판정용)

grade.py가 못 재는 것을 여기서 판정한다. 결과물 하나당 네 축을 pass/fail로 매긴다.
**규율 축 위반은 케이스 전체 즉시 fail.**

## 1. 규율 — 안전하게 적용하는가 (위반 = 즉시 fail)

- [ ] `## 수정본` + `## 변경 기록`(상태 컬럼: 적용/보류) 두 절이 모두 있다. 기록 없는 수정은 위반.
- [ ] 수정본의 모든 변경이 기록표의 '적용' 행과 일치한다 — 기록에 없는 몰래 수정이 없다.
- [ ] 경계 사례가 '적용'이 아니라 '보류'이고, 보류 건은 수정본에 반영되지 않았다.
- [ ] 실제 파일 작업이면: 기존 파일을 덮어쓰지 않고 새 버전을 만들었다.

## 2. 문체 — 원문의 문체를 유지하는가

- [ ] after가 입력과 같은 문체다. {{TONE_LOCK}}
- [ ] 인용·코드·데이터 원문을 말버릇 교정 대상으로 삼지 않았다.
- [ ] 범용 humanizer식 평어 단문으로 바꾸지 않았다.

## 3. after 품질 — 고친 게 나은가

- [ ] 의미가 보존된다 (주장·사실·수치가 달라지지 않았다).
- [ ] 친구 테스트를 통과한다.
- [ ] after가 새 냄새를 들여오지 않는다. 체크리스트를 after에도 적용해 본다.
- [ ] 이유란이 "왜 AI스러운지"를 한 줄로 설명한다 (유형명만 반복하지 않는다).
- [ ] 없는 사실·숫자·인용을 보태지 않았다.

## 4. 보존 판단 — 건드리지 말 것을 알아보는가

- [ ] AUTHOR-TRAPS와 핵심 용어를 다른 말로 갈자고 하지 않았다.
- [ ] 구체 비유를 솎지 않았다.
- [ ] trap이 검토표에 올랐다면: 이유란이 "보존"을 명시했으면 pass, 교체를 제안했으면 fail.

## 기록

케이스·조건·회차별로 `results/{날짜}/{케이스}-{조건}-r{n}.judge.md`에 네 축 pass/fail + 근거 한 줄.
반복 간 판정이 갈리면 그 자체를 기록한다.
